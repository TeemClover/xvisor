
# ชุดตัด rv (เครื่องยนต์ของสูตร DK-05)

ไฟล์นี้คือคู่มือคำสั่งของชุดตัดใน `kit/` ของสูตร DK-05 (ต้นแบบคือชุดตัด SK-03 ของสูตร DK-04 ชุดนี้ปรับเป็นโทน HabiX: คำเด่นสีเขียวโลโก้ ป้ายชื่อการ์ดครีม การ์ดสินค้ากลางจอเรืองเขียว ฉากปิดเรืองเหลือง ภาพ BF/AF และถอดเสียงทั้งเทปครั้งเดียว)

เทปยาวหนึ่งม้วน เข้า → คลิปสั้นหลายตอนที่ยิงแอดและลงโซเชียลได้ ออก งานแบ่งเป็น 2 รอบ:

- **รอบ 1 ตัดก่อน** ยังไม่ต้องมี insert: เลือกช็อต ตัด ใส่ซับ เสียง ฉากปิด ตรวจคำเสี่ยง ออกหน้าตรวจงาน
- **รอบ 2 ใส่ insert ให้ถูกคน** คนรับผิดชอบหาภาพ คลิปสินค้า ฟุตเทจ และสกรีนช็อตแอป มาวางในโฟลเดอร์ของแต่ละคน แล้วให้ AI วางลงช็อตของคนนั้น

`<skill>` ด้านล่างคือโฟลเดอร์นี้ ทุกคำสั่งรันในโฟลเดอร์โปรเจ็กต์ของงาน (โฟลเดอร์ที่มีไฟล์วิดีโอ) ผ่าน `<skill>/kit/rv`

## ต้องมีก่อน

- `ffmpeg`, Node 20+, `uv`, bash (Windows ใช้ Git Bash) และเบราว์เซอร์สำหรับวาดตัวหนังสือ (`npx playwright install chromium` หรือ Google Chrome ที่มีในเครื่อง)
- ตัวถอดเสียงเลือกตามเครื่องเอง: Mac ชิป Apple ใช้ mlx-whisper เครื่องอื่นใช้ faster-whisper (`lib/stt.py`) บังคับเองได้ด้วย `RV_STT=mlx` หรือ `RV_STT=fw`
- ครั้งแรก: `cd <skill>/kit && npm install && chmod +x rv` แล้ว `<skill>/kit/rv doctor` ต้องขึ้น "ครบ" (ถ้ารัน `rv` ไม่ได้ ใช้ `bash <skill>/kit/rv …`)
- ทาง faster-whisper ทดสอบแล้วบน Mac (บังคับด้วย `RV_STT=fw`) ยังไม่ได้ทดสอบบนเครื่อง Windows จริง ถ้าคำสั่งล้ม บอกผู้ใช้ตรงๆ อย่าเดา

## รอบ 2: insert

คนไม่ต้องแบ่งโฟลเดอร์เอง: โยนภาพและคลิปทั้งหมดลงโฟลเดอร์เดียว แล้วจับคู่ในหน้า HTML หน้าเดียว

1. คนรับผิดชอบวางไฟล์ทั้งหมดลง `inserts/_inbox/` (หรือส่งลิงก์ Drive ให้ AI โหลดลงโฟลเดอร์นั้น)
2. AI เปิดดูทุกไฟล์ รวมไฟล์ของคนเดียวกันเป็นชุด เขียนสิ่งที่เห็นในภาพ ข้อเสนอการจับคู่ และคำถาม ลง `inserts/_inbox/pairing.json` แล้ว `rv inserts page` → `จับคู่-insert.html` **AI ไม่ตัดสินว่าใครเป็นใครจากใบหน้า** เสนอได้เฉพาะจากข้อความหรือของในภาพ (ชื่อ อายุ แคปชัน สินค้าในฉาก) และต้องรอคนยืนยัน
3. ผู้ตรวจเปิดหน้า เลือกว่าแต่ละชุดคือใคร เป็นภาพชนิดไหน ใช้แบบไหนได้ ตอบคำถาม แล้วกด **บันทึกหน้านี้ลงเครื่อง** ส่งไฟล์กลับ หรือกด **คัดลอก prompt** ไปวางใน Claude Code
4. `rv inserts apply <ไฟล์ที่บันทึก>` จัดไฟล์ลง `inserts/<รหัสคน>-<ชื่อ>/<ชนิด>/` ให้เอง แล้ววาง `ins=[…]` ในช็อตของคนนั้นใน `edl.py` (ตั้งชื่อตอนเดิมต่อท้ายด้วย `i` ไม่ทับตอนเดิม)
5. `rv make <ตอน>` → `rv qa <ตอน>` → `rv risk` → `rv inserts page` (หน้าเดิมจะโชว์ตอนที่ใส่ insert แล้วพร้อมช่องความเห็น)

ทางเดิมยังใช้ได้: วางไฟล์ลงโฟลเดอร์ของแต่ละคนเองแล้ว `rv inserts scan`

กติกาการวาง ชื่อไฟล์ และสิ่งที่ห้ามใช้เป็น insert: `references/insert-round2.md`

## กติกาที่ห้ามข้าม

- **ห้ามแต่ง** ชื่อคน อาชีพ ตัวเลข เลข อย./ฆอ. ราคา ลิงก์ ถ้าเทปไม่ได้พูดหรือไม่มีแหล่งที่อนุมัติ ให้เว้นและบอกว่ายังไม่มี
- **ซับต้องตรงเสียง** ห้ามแก้คำพูดให้ฟังดีขึ้น ห้ามต่อคำข้ามประโยคให้เกิดความหมายใหม่ คำที่ฟังไม่ชัดให้ใส่ `check=` ในตอนนั้น มันจะขึ้นในหน้าตรวจงาน
- **หนึ่งคลิป หนึ่งแบรนด์** งาน Habix ไม่ปน Xircle
- **AI ไม่อนุมัติ** คลิประดับส้ม/แดง ใครจะยิงแอดต้องให้คนที่รับผิดชอบด้านกฎหมายหรือ อย. เซ็นผ่าน และผู้รีวิวทุกคนต้องเซ็นยินยอมให้ใช้ภาพก่อน
- **insert ต้องเป็นของที่มีสิทธิ์ใช้** ภาพทางการจากโฟลเดอร์ `assets/` ของ repo นี้ หรือของที่ทีมถ่ายเอง ไม่ใช้คลิปจาก YouTube ของคนอื่น
- **ภาพก่อน–หลังและภาพที่มีตัวเลขน้ำหนัก ไขมัน หรือจำนวนวัน เป็นระดับแดง** ใช้ได้เฉพาะชุดที่ผู้ตรวจเลือก "ใช้ภาพก่อน–หลังได้" ในหน้าจับคู่ ต้องเขียนใน `check=` ของตอนนั้นว่าเป็นระดับแดง และบอกผู้ใช้ตรงๆ ว่าติดข้อห้ามโฆษณาอาหารของ อย. และกติกาแพลตฟอร์ม การตัดสินใจเผยแพร่เป็นของคน
- **คำเตือนอาหารเสริม** ถ้าจะยิงแอด ตั้ง `"fda_warning": true` ใน `project.json` ฉากปิดจะขึ้นคำเตือน 3 ข้อ 5.8 วินาที ตัวอักษรสูงเกิน 1/25 ของภาพ (ให้ผู้รับผิดชอบ อย. ตรวจกับประกาศฉบับเต็มอีกครั้ง)
- **บอกผลตามจริง** `rv qa` กับ `rv risk` เป็นตัวช่วย ไม่ใช่หูกับนักกฎหมาย ทุกตอนต้องมีคนฟังและอ่านก่อนเผยแพร่ ถ้าขั้นไหนไม่ได้ทำ ให้บอกว่าไม่ได้ทำ
